# 玩家脚步设置与音频恢复（2026-10-25）

玩家音量从 .10 调整为 .085，降低15%的线性增益；这是小幅混音调整，不宣称主观响度恰好降低15%。NPC音色、步频和增益保持原样。

按用户要求核对 Mojang [官方声音定义](https://github.com/Mojang/bedrock-samples/blob/main/resource_pack/sounds/sound_definitions.json)：step.stone、step.grass、step.wood 属于 player，ambient.cave 属于 ambient，雨声属于 weather。参考这种分类分离，在“设置 → 音乐与环境音效”增加“玩家脚步”开关，单独保存到本机偏好 block-island-player-footsteps-v1。它控制玩家步行和跑步；NPC仍随环境音。关闭环境音也不再连带关闭玩家脚步。未引入完整Minecraft声音分类系统，也不声称官方有同名独立脚步按钮。

音频增加一个独立GainNode，把原共享脚步播放器的玩家输出接到此总线；原NPC输出保持接原环境总线。原四个并发短音源上限、三个玩家材质缓冲与释放责任不变，没有第二套PCM播放器、音轨或定时器。关闭玩家脚步时立即静音总线、重置步频，后续移动不创建玩家脚步节点；主声音关闭、暂停、隐藏、销毁仍控制所有脚步。

本轮对实际physics做10–240FPS、45秒不等帧间隔平地行走诊断，未复现用户的偶发断声，未修改移动/碰撞。发现并定向复现另一条缺陷：Web Audio被系统中断时，游戏移动仍继续，旧混音器仍向被冻结的音频时间排入脚步，直到占满四源上限，也不主动恢复。新逻辑在非running状态停止脚步和节奏，只在正常游玩且非closed时尝试resume；最多每秒一次且仅一个未完成请求。恢复后从当前移动重建节奏，避免补播中断期间的声音。主声音/环境和玩家脚步全关、页面隐藏或销毁时不重试，不改变浏览器许可或用户Chrome。

回归模拟Web Audio中断、恢复、closed与时间冻结，覆盖45秒不等帧持续移动、单独设置持久化、NPC/车辆不受玩家开关影响和双向分类独立。中断前未修代码能排满四源，候选不再排入且恢复行走声。该结果证明已处理的代码路径，不能确认用户当时的浏览器确实处于此状态；本轮没有实机试听或用户浏览器操作。API依据见[Web Audio规范](https://webaudio.github.io/web-audio-api/)。保持存档6、地图11、缓存84和已有画面/人数/视距，无普通小修公告。
