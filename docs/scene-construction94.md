# 外滩静态缓冲与寻路临时内存 · 2026-10-23

基线main `d910e80`。用户明确外滩持续运行比园林更重要，本轮保留已经验证、可减少初始构造开销的两项小改动，后续重点转向外滩移动与转视角的完整帧成本。未调整清晰度、抗锯齿、视距、人数、灯光效果、交通时钟、地标或存档。

## 外滩构造

原静态街景合批先将顶点、法线、UV、索引写入大量普通JS数组，随后复制为GPU类型数组。现在先按原顺序收集同材质/昼夜组的来源，统计长度，直接写最终缓冲。使用BufferAttribute避免Float32BufferAttribute的再次复制。保留原世界变换、逐顶点法线归一化、索引顺序、包围球、材质和昼夜分组。车、人、船、钟等原动态排除项不变。

测试对照原writer的GPU字节，覆盖层级/负缩放变换、无UV、indexed/non-indexed、空组、65535 primitive-restart边界及未引用的大顶点数组。该优化发生在构造阶段，不宣称直接提升外滩持续帧率。

## 园林搜索

保留原半米网格BFS和四方向顺序；用可复用、有固定容量的队列、父节点及代数标记，替换每次搜索的大量数组/字符串/Map。有效范围仍为原来的x[-120,32]、z[206,336]，三份缓冲共955,260字节，首次需要时分配。结果坐标路径按原顺序返回；中点净空、动态占用及阻挡查询照常执行。非标准网格/范围输入回退原搜索。未缓存最终路线或碰撞结果，原reroute的净空缓存清理继续保留。

65组精确路径对照包含绕墙、动态占位、重复调用、相同起终点、边界、非网格和范围外输入；额外核对净空回调顺序与失败后重新搜索。真实World的62名外围游客和3名内园游客通过12分钟变帧率进展、独立浏览、无瞬移/穿墙、暂停及玩家新增障碍恢复检查。

## 性能证据和边界

同机独立Node进程交替各三次，构造World、外滩、城市活动、地铁、豫园及最终实例/补光，假DOM/Canvas不含真实文字栅格化与GPU：

- 园林构造阶段中位约3,256→2,929ms，约减少10%。
- 外滩构造时间中位约1,873→1,919ms，差异处于样本波动范围；不声称外滩构造提速。
- 另一次最终源码的三轮交替记录整个进程maxRSS：原版836,124–849,972KiB，候选738,244–739,752KiB；中位849,480→738,832KiB，降低约13%（约108MiB）。这是该Node构造工作负载的进程驻留峰值，不是手机实际内存、JS存活堆或显存；不混用指标。
- 对象15,046、mesh11,669、geometry4,025、material3,761、texture605、实例批315保持。

本机完整WebGL各三组交替，固定QA画布1055×487、MSAA开启、seed94、静音禁存档、默认地图缓存强制未命中：导航ready中位12,229→12,183ms，变化不到1%；模块构造中位9,799→9,722ms。未取得明显整体加载提速。保留本轮的依据是有验证的构造内存收益与搜索分配减少，不能将局部耗时改善宣称为总加载或整机FPS提升。

两版均为1,345次绘制、820,434个三角形、160已加载/128待处理区块，最终候选无控制台警告/错误。此前未固定实际画布的探索样本及编辑源码期间的早期Node样本已排除。没有连接手机，本轮无需用户反复配合手机操作。

原始记录仅本地：`.local-data/qa/garden94-scene-benchmark.json`、`garden94-memory-benchmark.json`、`boot94-comparison.json`。该轮源码增加两项测试至47项发布检查。后续按[长期规划](performance-roadmap.md)集中检查外滩完整帧，不能反复扩大园林优化或以降低清晰度换取收益。
