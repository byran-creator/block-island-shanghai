# 第55版：内存与车夫声音

本轮保留第54版的建筑、材质、灯光、贴图尺寸、游客数量、动画和视距，针对用户实际遇到的内存不足提示和车夫远处喊话处理。没有改动存档版本、地图修订、个人编辑数据或城市基础缓存版本。

## 原因与改动

- 游戏常驻保留一份56,070,144字节的基础体素副本，主要用于重置城市和判断地铁保护。现在保存为按连续值编码的只读基线，2,849,695字节，减少53,220,449字节（50.75 MiB）；随机查询用二分定位，整图重置按段填充。高熵输入自动退回原始字节副本，避免压缩反而膨胀。
- 静态模型合批原先先生成多组JavaScript number数组，再复制成GPU属性需要的类型数组。改为先计数、再直接填最终类型数组，单个网格直接复用。保留来源共享几何，不贸然dispose仍可能被动画对象使用的资源。
- 车夫原有锯齿波“喉音”和系统TTS叠加，且避让行人时走了无距离限制的全局播音路径。现在所有吆喝都走同一个控制器：8米外不请求、不解码、不播放；2米内正常音量、2—8米衰减，楼层差超过3米静音；全车队同一时刻只允许一个声音，普通吆喝至少间隔10秒。上车/下车可替换正在播放的吆喝。
- 三段普通话男声采用预生成合成配音，不冒称真人录音。素材来源与制作参数在游戏音频署名中。仅首次走近时按需加载，解码后复用；暂停、切后台、关环境音、总静音、音量归零、离开范围或读档均停止，并释放播放节点。失败不回退到原电子喉音，30秒后才允许重试。

## 验证与限制

- 当前整幅城市基线逐字节还原、抽样读取、编辑后重置、原存档个人建造与黄包车读档兼容通过。
- 嵌套旋转/非均匀缩放、索引/非索引、缺省法线/UV、颜色、可见性/材质分组、单例与32位索引均测试通过；8辆车4组姿态的顶点/法线/UV/材质量化一致。
- 相同Node脚本、分开的串行进程、相同世界和模型：第54版峰值RSS595,704 KiB，第55版406,800 KiB，下降约31.7%。两者2,798网格、718,678三角形，全部几何属性/索引SHA256一致：`4e0b91ef6b29894298f0d3dab9396296b8d757f3734bb890e6bc748c2144b0ad`。这是可复现的构建阶段CPU进程测试，不是整机内存、浏览器总占用或FPS承诺。
- 三个MP3合计78,192字节；本机浏览器静音解码成功，24kHz单声道合计1,251,072字节，最长4.8秒。播放控制测试覆盖远近、楼层、8车争用、冷却、解码复用、音量、暂停、异步返回取消和离线退避。
- 本机浏览器使用Intel Iris Xe；本轮默认1280×720，与上轮614×614不同，且自动化采样rAF约每秒一次，故不据此前后对比FPS或声称消除所有卡顿。密集夜景仍有渲染负担。本轮不降低画质，也不扩大到旧车流问题。

复现：`node tests/world-baseline.test.mjs`、`node tests/mesh-batch-memory.test.mjs`、`node tests/rickshaw-audio.test.mjs`、`node tests/yuyuan-save-compat.test.mjs`、`node tests/yuyuan-rickshaw-batch.test.mjs`。模型与基线测试在Node下；真实MP3解码另在本机浏览器完成。
