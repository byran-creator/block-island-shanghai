# 偶发卡顿优化 · 2026-10-06

移动时的地图网格生成由一次生成整批区域改为分帧工作。每帧约3毫秒预算、最多提交一个完成网格，优先处理玩家附近区域；快速移动时取消已不需要的任务。搭建修改会取消过期任务，已有画面在替换网格完成前保留。首次载入和读取存档仍完整准备地图；远距离传送后的周边画面逐步补齐。碰撞继续读取完整方块世界，因此不依赖显示网格的加载进度。

骑手在堵塞时的A*绕行搜索原先可能在一次更新中连续搜索多个目的地。现在搜索按节点分段、轮流处理，每次交通更新约2毫秒预算；绕路的每一步仍检查当前车辆、建筑与信号。取消已离开起点或恢复通行的搜索，没有删除碰撞或减少角色数量。地图缓存修订和玩家存档格式不变，没有新增整份世界副本或驻留地图缓存。

## 对照结果及边界

相同45秒游戏路线、固定1/60秒逻辑步长、2700次更新、晴天、同一514×614画面。浏览器绘制回调被运行环境降频，所以用测试页面按固定次数驱动游戏更新，测量每次更新的同步耗时。这不是实际帧率，也不能把固定步长的16.7毫秒间隔换算为60fps。

| 指标（毫秒） | 旧版 | 优化版 |
| --- | ---: | ---: |
| 更新耗时中位数 | 18.6 | 11.1 |
| 更新耗时95百分位 | 28.6 | 17.1 |
| 单次更新最高耗时 | 160 | 61.2 |
| 超过100毫秒的更新次数 | 3 | 0 |
| 地图需求更新最高耗时 | 58.5 | 1 |
| 分帧网格工作最高耗时 | — | 3.6 |
| 交通更新最高耗时 | 149.6 | 10.6 |

两版结束时均有417个地图区域、101次绘制、1148份渲染器几何资源，优化版没有待处理网格。没有通过减少最终显示内容来比较。同步耗时还受到系统调度、浏览器预热与垃圾回收影响，不承诺其它设备或场景有同等改善。

两次堆内存采样分别约524与732MiB，受垃圾回收时机影响，不能据此声称内存减少，也不能据此证明内存泄漏。该批优化主要针对集中计算停顿，没有解决所有显卡、内存或驱动瓶颈。测试设备为i5-12500H、Intel Iris Xe、15.6GiB内存，系统空闲内存采样约1.9–2.2GiB；这些是当时情况，不是硬件最低要求。

## 验证

11个真实城市区域的顶点、法线、纹理、颜色和索引与旧实现逐项完全一致；独立8列分段最长约2.8毫秒。新回归覆盖跨区边界、过期网格失效、快速移动取消、单帧提交上限和分段绕路等价。原15分钟车辆/骑手碰撞与障碍恢复回归、车道、地铁、通勤、缓存和本地存档回归均通过。浏览器试玩静音且禁用存档写入，测试页不包含在发布包或公开源码中。
