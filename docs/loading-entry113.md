# 点击开始后加载城市与配乐（113）

用户实测免触碰播放时有时无，明确选择并再次授权采用“先开始、后加载”。不再以移动歌名或网页请求已发起来代表手机已经出声。

## 入口与音频

初始HTML只显示轻量欢迎画面和原“开始旅程”。主程序URL仍使用内容哈希，但放在惰性配置中，浏览器不会提前下载/求值主程序或创建整座城市。现有203KB默认地图快照预加载保留；不清空世界缓存、个人建造或存档。

原开始按钮的真实click捕获阶段同步调用HTMLAudio.play，并创建/恢复一个页面共享的WebAudio上下文；接着才插入主程序module脚本。没有await、定时器或SDK权限调用插在首次启声之前。加载音乐沿原同站片段循环至真正进入游戏；保持已静音偏好、前后台处理、异常与迟到Promise清理。

`audio-context.js`以页面全局Symbol持有唯一上下文，欢迎脚本和后续游戏bundle独立打包后仍采用同一个实例，不在准备完成后重新创建一个未激活的上下文。页面拥有该资源；暂停/返回菜单不反复创建或关闭。原游戏音量、配乐、雨声、江水和脚步不改。

城市就绪后等主程序完成ready处理，再调用原开始按钮的存档恢复入口。原有未读公告仍等待用户确认，然后自动继续；不会再要求第二次点击开始。恢复失败保留原错误与重试。后续暂停菜单的模式、设置、传送和手册入口仍保留。首次欢迎画面用小型原创SVG，不创建3D城市；进入后原场景、开场和任务流程照旧。

主程序下载或求值失败仍有独立经典脚本提供详情/手动重试；30秒计时从开始点击起算，而非用户停留欢迎页起算。迟到进度恢复原禁用控件，ready释放观察器/计时器/错误监听。播放器错误不阻断城市加载。

## 检查与边界

定向回归覆盖未点击无主程序请求、音频事件先于模块插入、重复点击只加载一次、公告/存档原入口衔接、错误/超时/迟到进度；真实生产音频bundle在模拟真实点击栈中启动，并验证第二个独立bundle复用相同上下文。独立静音WebGL页面实际验证欢迎→构造→原公告→自动进入；测试源独立、音频接口禁用，不动玩家存档或Chrome。这不是手机微信的扬声器/播放许可验收。

`__`开头的专用QA页面保持原有自动加载、就绪不自动进存档的契约；不得把这个自动旁路当作真实用户点击启声测试。正常分享入口必须点开始。

一次本地prebuilt-world检查在无快照worker重建用例触发原10秒夹具期限，继而走回退导致worker断言失败；诊断副本记录了`QA_WORKER_TIMEOUT missing`。未放宽期限或修改世界生成器。世界Worker/快照内容未变，发布仍需完整CI检查；不称本地所有检查通过。城市构造时间没有因此被证明缩短，历史navigation→ready统计现在可能含欢迎页停留，后续比较需另记点击开始时刻。
