# 手机快速转向：纹理复用与隐藏矩阵树 · 2026-10-23

基线 main `fbb1c23`。用户反馈手机仍低帧率；iPhone 15 Pro Max 在微信及 Safari 快速转视角时会自动重载。本轮没有该手机的崩溃日志或远程连接，因此不能把浏览器重载直接认定为某一种内存/GPU/系统故障，也不能声称已经在真机排除。

构造审计发现重复的地铁静态标牌分别创建 CanvasTexture，一些画布为 3456×256。保留原尺寸、文字、箭头、颜色、各面及 mip/各向异性，按完整绘制参数复用相同不可变画布与纹理。缓存属于单个 createMetro 根节点，与该地铁场景同寿命，不是跨场景全局缓存；运行中的到站屏和车厢线路屏使用独立画布。静态牌若后续重绘，首次变化分离为私有画布，此后复用该私有画布；没有把每一个倒计时结果不断加入缓存。场景整体退出时应释放场景持有的材质/纹理并丢弃该地铁实例，未来区域卸载不得把它保留为全局表。

同一 Node 构造范围内纹理对象 605→544，RGBA 加完整 mip 层的理论数据量 464386731→380907520 字节，约少 79.6 MiB。该估算不是实测 iOS 显存或总内存；包括可能未上传的纹理，不包括 CPU 画布副本、驱动及系统开销。几何字节 115006408、对象/mesh/geometry/material 数量保持。完整游戏的实际驻留纹理计数另记录。

快速转向采样还指出场景矩阵树每帧约 9–10ms。现有 metro-visuals 已能把远离入口的地下内容设为不可见，但 Three.js 仍会更新这些隐藏分支。本轮只让这个明确隐藏的地下 Group 跳过渲染矩阵递归；地铁、行人、门和时钟的模拟仍运行。显式 getWorldPosition/updateWorldMatrix 查询保持原实现；重新靠近入口、进入地下或玩家编辑使遮挡失效时，首帧强制刷新完整矩阵树。没有给整个引擎增加“隐藏就停模拟”的通用规则。

针对性回归覆盖共享静态牌、原像素绘制尺寸、正反箭头/线路参数隔离、重绘分离、不变内容不上传、动态屏独立、隐藏时坐标查询、父子变换、入口/地下首帧恢复及玩家编辑豁免。原地铁标牌、双面方向与到站更新和启动兼容测试通过。固定画质完整对照见最终采样补充。

完整 WebGL 快速转向固定 1055×487、MSAA、seed98、夜间、静音禁存档，100帧排前20帧；原版/候选交替三组。各组帧函数中位为原63.9/63.1/39.4ms，新65.4/40.3/43.7ms；P95原108.4/117.7/69.3ms，新97.7/75.5/75.6ms。环境波动大，第一、第三组中位没有改善，第三组P95没有改善，因此本轮不宣称稳定整帧/FPS提速，更不能把中位汇总换算为手机提升比例。矩阵阶段均值原12.78/10.40/6.51ms，新11.16/4.92/4.92ms，只可作为局部减少隐藏工作的依据。
