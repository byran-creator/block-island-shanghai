# 手机加载页音乐触摸恢复（2026-10-25）

用户明确反馈加载页没有《上海滩》，进入游戏后的配乐正常，因此只改轻量加载播放器，不修改游戏内音轨、脚步或环境声。

旧控制器在首次play尚未settle或audio.paused已变false时直接返回，真实触摸也不能再次同步调用该媒体元素的play。回归复现了“自动请求pending、paused=false、随后touchend”的漏重试。现在允许一次真实手势请求替代自动请求，手势请求本身未完成时不重复创建请求；用尝试编号忽略旧请求的迟到拒绝，避免已播放却显示被拦截。暂停/静音/进入游戏使旧编号失效，进入后迟到完成仍停止并释放媒体。

触摸、指针、按键和点击监听改为document捕获阶段，以免子控件停止冒泡导致加载页没有收到正常交互；不阻止默认操作，也不吞事件。销毁按同一capture标志解除。初始准备与被拦截提示均明确显示《上海滩》和轻触启声；默认播放尝试仍保留，不修改浏览器权限。

这是对已复现控制器缺陷的修正，不是实际手机播放成功的证明。[WebKit官方媒体策略](https://webkit.org/blog/6784/new-video-policies-for-ios/)仍要求用户手势；[HTML媒体规范](https://html.spec.whatwg.org/multipage/media.html)允许浏览器限制自动播放。不能承诺手机第一次打开即有声，未模拟微信授权桥接，也不为此访问用户Chrome或请求操作手机。若此前未触摸加载页，则静音也可能只是正常浏览器限制。

新增回归先失败再修复，覆盖pending自动请求→真实触摸、一次未完成手势请求的去重、迟到拒绝、捕获监听清理，并保留静音/隐藏/设置/循环/进入游戏释放检查。资源仍是原176,795字节同站哈希片段，未新增下载、解码或定时器，不改Save6/Map11/Cache84与画质。

## 首屏入口补充

用户手机实测仍需下滑才能看到配乐。旧说明处于滚动菜单中，前面有标题、介绍和开始按钮，短横屏容易把它挤出首屏。现在将同一个配乐区域移出滚动菜单，固定在视口右下角，并增加原生“轻触启声”按钮；保留出处链接与状态。按钮直接由播放器管理，点击调用同步手势重试，dispose解除自身监听；播放成功、静音或退出加载页时隐藏启声按钮，真正进入游戏后隐藏整个配乐区。默认播放尝试与手机浏览器手势限制不变，不承诺免交互播放。

只增加有限布局样式和按钮事件，无持续扫描、轮询或新音频资源。菜单底部在配乐区显示时保留空间，避免固定入口盖住最后一项。相关回归覆盖配乐区不在滚动容器内、原生按钮独立触发、监听释放；自动播放和原有控制器回归继续保留。

本轮尝试打开独立静音本地布局页，但回环访问超时，随后连接该标签的动作被自动审批拒绝，理由是用户此前不允许浏览器操作。没有继续浏览器动作或切换到Chrome，专用预览服务已停止。不声称横竖屏截图验收或手机试听已完成；代码/构建验证与此限制分别记录。
