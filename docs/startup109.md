# 微信加载反馈与入口诊断（109）

用户反馈普通 GitHub 分享页在手机微信停留于“正在加载城市与建筑…”，不是 preview。此文案来自 HTML；正常主程序在画面初始化后、读取缓存时会更新它。本轮不把这个症状误归因于缓存读取，也不发布已另行暂存的缓存超时候选。

已检查当时线上 HTML、主脚本、Worker、世界快照、样式与同站音乐片段：HTTP 200，字节与发布构建一致。这仅证明本机当时能取得资源，不能排除用户微信网络、内核或内存故障。

独立静音、独立源、浏览器存储测试页中，发布108与候选109在现代浏览器均能到达 `block-island-ready`。只在测试文档移除 `Array.prototype.at` 可复现初始提示不动：`city-layout` 模块求值时报 TypeError。这个兼容性夹具不是微信模拟，也不是用户故障的确诊。当前构建还使用 ES2022 / 顶层 await；不能仅加一个 at 补丁就声称兼容旧微信内核。

## 本轮范围

- HTML 内独立经典脚本捕获主入口下载/执行错误，显示可展开的本地错误详情及手动重载；不发送遥测、不读取或删除存档，不自动刷新。30秒仍未离开最早两阶段时给重试，后续地图构建阶段不误报下载超时。迟到的正常进度恢复原控件，ready 时释放监听、观察器、计时器。
- 画面初始化增加独立阶段文案，区分脚本尚未执行与渲染器初始化。
- 加载音乐继续默认 play；额外监听一次微信 `WeixinJSBridgeReady`，同步再试一次。无需 SDK、伪造签名、网络权限调用或轮询；失败仍显示原生启声按钮。此事件不能保证所有微信版本免手势播放，当前未进行用户真机听音验收。暂停、静音、迟到播放 Promise 和进入游戏后的释放保持原规则。
- 音乐入口路径检查移除自身非必要的 `.at` 依赖；没有把游戏引擎整体改为旧浏览器兼容构建。

验证：`startup-entry` 覆盖独立错误反馈、慢启动、迟到进度、音乐错误隔离、ready 清理；`loading-music` 覆盖桥接时机的有界重试、后台不播放与释放。独立发布构建页验证了真实模块错误的可重试提示与重载、正常移动入口就绪且帮助隐藏。日志中保留注入故障，不把它当新错误。没有进行真实微信重测，不能据此宣称用户加载故障已修复。若仍失败，下一步依据同一用户页面的错误详情定位，或取得真机远程日志；不继续猜测性修改缓存、存档或画质。
