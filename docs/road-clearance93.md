# 道路净空计算与加载优化 · 2026-10-23

基线main `1e9db27`。构造CPU采样发现 `distanceToRoad` 在模块初始化期间反复扫描全部道路点，调用者实际只判断距道路是否小于1。替换为保守包围框筛选及首次命中返回，保留原采样点、Math.hypot、道路宽度和严格小于边界。内部缓存保存该布尔判断，建筑生成顺序不变。

道路布局全部初始化完成后，为运行时 `roadContains` 建立8格静态索引；采样点按完整净空范围登记到所有覆盖格，查询仍执行原距离谓词。索引有极小保守边界余量，不改变最终距离判断；没有交通计时或玩家方块缓存。未来运行时修改道路必须重建索引。未调整渲染矩阵、画质、人数、贴图、地标或原空间布局。

## 证据

- 19,840组原最近距离谓词对照，含随机位置、严格边界和方向；布局与道路序列SHA均为 `4cf814a203fbad8adb6ecfbb52961c705e899b3c5c2fd59f7c930f54ef76d65a`。
- 默认体素及surface SHA与92一致。存档6、地图11、cache84和默认地图buildId内容保持，玩家编辑继续叠加。
- Node独立进程交替三轮：模块初始化中位5,484.6→1,146.2ms；每4,000次查询中位53.47→1.70ms。是本机CPU工作负载，不是整机FPS。
- 本机WebGL三组交替样本：导航到按钮就绪中位18,384→13,224ms（约28%减少）；两版画布1055×487、MSAA开启、1,345次绘制、820,434个三角形、160已加载/128待处理区块一致，最终页面无控制台警告/错误。
- 该WebGL测试静音、禁存档、固定seed93、默认地图缓存强制未命中；使用发布快照及打包入口、本地HTTP。首次错误尺寸样本被排除。本轮机器整体比92轮慢，不能与上轮9.6秒直接跨轮比较；结果也不代表手机、公网冷启动或持续运行帧率。

原始本地记录：`.local-data/qa/road93-benchmark.json`、`boot93-comparison.json`、`startup93.cpuprofile`。公开仓库仅保留不含个人资料的测试与复现脚本。`npm run bench:roads`可复现运行时CPU查询对照，使用交替顺序，不在共享CI按毫秒硬判失败。

新增道路测试纳入发布检查；现有交通、船体、行人混行、地图及存档回归继续使用。长期约束见根目录AGENTS与[攻坚规划](performance-roadmap.md)。本轮完成首个热点；四区完整真机路线、静态场景更新和区域资源生命周期仍是后续任务，不宣称已完成全部规划。
