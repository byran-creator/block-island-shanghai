# 手机流畅模式、摇杆与自动横屏

默认手机流畅模式使用不超过0.9的像素倍率，且长边不超过1000个渲染像素，关闭MSAA抗锯齿。常见手机尺寸相对原1.25倍率的像素量为51.84%。默认以30帧为渲染目标；设置可切清晰模式（最高1.25、长边1400、60帧目标）。桌面倍率、抗锯齿和原帧率保持。帧调度只在真正处理一帧时更新时间基准，跳过的rAF时间留给下一帧dt，原人物/交通/物理的时间和内部小步检查保留。

手机原地形请求以240米覆盖大量已在150米雾外的普通建筑、河岸。现在普通建筑/河岸150米，玩家周边9×9区块和240米内主要地标仍保持；远离后释放不再需要的地形网格，原世界、方块和碰撞不删除。移动不足8米不重复扫描/排序同一地形队列，强制重建和即时到达不跳过。实际生成器请求对照：外滩588→288、上海中心443→226、豫园363→182。三个地点桌面请求集合与原版逐项相同。这是请求数与像素预算对照，不等同真机帧率或总内存减半。

触控HUD的常驻按钮/热栏关闭实时背景模糊，保留原颜色与布局。未改光照、建筑纹理、NPC人数、路线、玩家存档或城市基础缓存。

摇杆默认启用，径向12%死区，超出后按推量连续控制走速，360度方向与玩家视角相对，斜向不加速；跑步按钮仍可用。设置可切原十字键，仅保存本机偏好。键盘与摇杆使用独立输入，松手/取消/失去捕获/暂停/失焦/切方向/传送清除摇杆。第二根手指不接管已按住的摇杆；右侧视角触控仍独立。车内步行也接收同一模拟轴，载具沿原按键接口接收方向。

手机默认横屏布局。竖持时先使用已有CSS旋转；点击开始时才尝试原生全屏与横屏锁定，失败保留CSS布局，适用于缺少这些API的微信网页容器。实际设备已经横屏时不会重复旋转；旋转后的摇杆和右侧视角均做逆坐标映射。玩家可切回竖屏，选择保存在本机；晚到的原生请求结果不会覆盖玩家新选择。使用实际innerWidth/innerHeight设置旋转容器大小，避免浏览器工具栏导致裁切。

原生API限制参考：[MDN ScreenOrientation.lock](https://developer.mozilla.org/en-US/docs/Web/API/ScreenOrientation/lock)、[MDN requestFullscreen](https://developer.mozilla.org/en-US/docs/Web/API/Element/requestFullscreen)。网页自动横屏布局不代表一定能旋转系统状态栏，也不需要小程序或安装。

验证：`mobile-runtime.test.mjs`覆盖64个方向、轻推/死区/最大幅度、斜向限速、旋转坐标、取消与第二指、本机偏好/存储不可用、原生API成功和失败/迟到结果、60/90/120Hz调度且模拟时钟不变。原手机布局、地铁车厢/10号线、增量地形队列、菜单建筑预热与手册回归。浏览器短组件验收使用真实HTML/CSS/控制模块、静音且不写玩家存档；844×390与390×844验证布局、摇杆拖动/释放、设置切换和手动回竖屏。未把桌面浏览器的设备尺寸模拟称作真实手机/微信帧率测试。
