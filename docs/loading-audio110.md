# 加载音乐初始化时机（110）

109发布后用户确认手机微信已能进入游戏。用户再次明确：没有点启声按钮，是滑动页面后才出声；要求默认播放并移除“轻触启声”提示。本轮不改游戏内配乐、脚步、环境声、主引擎、存档或画质。

加载播放器原为外部 ESM，需下载后延迟求值，存在晚于微信早期桥接就绪事件注册监听的窗口。Pages 与 Sites 共享一个构建助手，将同一播放器打包为小型内联经典脚本，在其署名节点之后、主菜单和游戏模块之前执行；无额外脚本请求和 ESM 求值等待。源码开发入口仍为同一模块。相对音源以 document.baseURI 解析，覆盖根路径、GitHub仓库子路径及 preview 子路径；MP3内容哈希及存档路由不改。内联代码使用ES2019语法目标、不包含音乐二进制、不添加微信SDK或签名调用。

页面解析到播放器时立即尝试 play，早期 WeixinJSBridgeReady 可再试一次；保留正常页面交互后的自动恢复。移除启声按钮和引导文字；只有实际播放 Promise 成功才显示歌曲署名，准备/受限/静音状态不假装已经播放。默认尝试与免手势成功是两回事，WebView拒绝播放时无法靠改提示强制获准，未宣称所有微信无需触碰即可有声。

验证同一生产内联代码在主游戏控件尚未创建时启动，覆盖无触摸/滑动的初始调用、桥接事件恢复、根/仓库/preview音源URL、已静音/QA页不播放、进入游戏释放。构建兼容测试检查真实Sites HTML已内联且不再请求单独音乐模块；保留主入口哈希、Worker/快照、浏览器与云存档回归。此类模型化时序测试不等于真机微信播放许可或扬声器试听。
