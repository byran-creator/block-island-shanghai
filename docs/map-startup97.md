# 地图布局与启动底图 · 2026-10-23

基线 main `e2e1aa0`。手机横屏地图的第一列原本用 flex 布局，画布高度只扣除了固定说明高度，没有为当前任务卡预留空间。在 844×390、有当前任务的实际 CSS 对照中，画布底部到 411px，传送列表从 417px 开始且可用高度为 0。生活岛入口因此难以触达。

短横屏改为明确分配任务提示、剩余地图区域和 68px 可滚动传送列表；对话框靠上，手机列表优先显示生活岛，按钮保留至少 32px 高。地图本身仍使用原始绘制分辨率，桌面布局与传送落点/碰撞判定不变。横持 844×390、740×360 和竖持强制横屏的隔离页面均核对可见边界与生活岛按钮点击。没有使用真实玩家存档。

启动时生成小地图底图仍会逐列从世界顶部向下调用 ground/get，并为每个像素解析颜色。新增 map-background.js 只在标准 VoxelWorld 数据布局和接口未覆写时直接读取同一体素缓冲；非标准对象仍调用原接口。调色板每次生成只解析一次，写入原有 ImageData，不增加常驻高度索引、地图缓存或额外全图像素缓冲。

不能用地形 surface 数组代替最高体素：屋顶、树木和玩家搭建都可能高于地面。回归按原算法逐字节核对 389376 个 RGBA 像素，并覆盖空列、世界顶部、临水高度、未知方块、编辑后删除、覆写接口和复用输出缓冲。默认城市/个人编辑、存档格式和缓存版本均不变。

本机 Node 24.12.0 三次交替 CPU 对照的中位数为 310.14→55.75ms（约 254ms）。这是底图生成局部 CPU 计时，不是手机下载、完整加载、FPS 或所有设备的收益保证。完整 WebGL 启动对照另附本轮最终结果。

本地完整 WebGL 启动对照使用两份最小化打包、固定 1055×487 实际画布、MSAA、seed97、静音禁存档、默认地图缓存强制未命中；快照保留，启动后停止帧循环及后续预热。三组顺序为原→新、新→原、原→新。地图创建阶段三次中位 500.5→188.2ms，入口模块执行至相同 ready 点中位 16122.2→15450.3ms，约 4.2% 的小幅改善。首次样本有明显冷启动波动，其他阶段也有噪声，不能把整个差值全归因于地图，更不能承诺手机或正式网络加载缩短相同比例。没有达到加载减半；后续主要成本仍是场景构造和首屏准备。

六次的 drawCalls=1345、triangles=820434、chunks=160、pending=128 和画布/抗锯齿一致，最终控制台无警告/错误；地图逐像素对照通过。证据为本地 qa/map97-cpu.json 与 qa/boot97-comparison.json。本轮没有连接手机，也没有修改画质、人数、视距、地标、灯光或存档接口。
